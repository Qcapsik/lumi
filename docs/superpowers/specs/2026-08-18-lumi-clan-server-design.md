# Спека: Луми — автонастройка Discord-сервера RUST-клана

Дата: 2026-08-18
Проект: Lumi (Discord-бот, `D:\AI_CORE\`)

## Цель

Дать Луми возможность самостоятельно разворачивать полный Discord-сервер игрового клана по RUST по одной фразе («настрой клан сервер», «сделай сервер для клана RUST»), включая роли и права, разделённые ветки общения, приватные ветки для шефа и подгрупп, тикеты-заявки на вступление, мониторинг дней рождения, приветствие новые участников с правилами и помощника по выдаче ролей. Дополнительно — бонусный модуль интеграции внешних ботов (Juniper и др.) через официальные инвайты.

ВАЖНОЕ ОГРАНИЧЕНИЕ ПЛАТФОРМЫ: Discord не позволяет боту создавать других ботов или приглашать их на сервер — это доступно только владельцу сервера кликом в окне авторизации. Луми умеет: (а) делать все подсистемы сама, (б) генерировать официальную invite-ссылку и настраивать права для уже добавленных внешних ботов.

## Архитектура

Решение строится на существующей структуре кода (следуем существующим паттернам):

```
bot.py               — точка входа, SYSTEM_INSTRUCTION, TOOLS_DECLARATION, tools_map, события
discord_tools.py     — новые AI-инструменты (setup_clan_server, generate_bot_invite, ...)
components.py        — новые интерактивные панели (дни рождения, приветствие, роли-по-подгруппам)
database.py          — новые таблицы и CRUD (birthdays, welcome_config)
```

Подход: один новый «пресет»-инструмент `setup_clan_server` плюс три подсистемы (ДР, приветствие, внешние боты) как отдельные инструменты и фоновая задача. Гарантированная структура, затем Луми может донастраивать детали существующими инструментами.

## Компоненты

### 1. Инструмент `setup_clan_server` (discord_tools.py)

Параметры: `server_name`, `clan_name`, `subgroups` (list, по умолчанию 5–7: Ферма, Экономика, Рейды, Стройка, Ивенты, Снайперы, Разведка), опционально цвета.

Фазы:
1. **Подтверждение удаления.** Первый вызов без `confirmed=true` возвращает сводку: что будет удалено (каналы/категории/роли без @everyone и managed) и что создано. Луми спрашивает пользователя; при согласии вызывает повторно с `confirmed=true`.
2. **Удаление** существующей структуры (только не-managed, не-deafault).
3. **Роли** (создаются снизу вверх по иерархии):
   - 👤 Гость (#99AAB5, не hoist)
   - 🔸 Новичок (#7289DA)
   - 🔰 Член клана (#3498DB)
   - ⭐ Ветеран (#F1C40F)
   - 🎖 Офицер (#E67E22)
   - 🧠 Заместитель (#9B59B6)
   - 👑 Шеф (#FF4654)
   - Роль-роль подгруппы на каждую подгруппу (🎖 Ферма и т.п., #2ECC71)
4. **Категории и каналы** с правами:
   - `📌 ИНФОРМАЦИЯ` — 📢┃объявления (announcement, могут писать только Шеф/Зам/Офицер), 📃┃правила (embed правил + send_verification_panel), ℹ️┃инфо (welcome embed)
   - `👑 КОМАНДОВАНИЕ` — виден только Шеф+Зам+Офицер: 💬┃правление, 🗣┃штаб (voice), 🛡┃модерация
   - `💬 ЖИЗНЬ КЛАНА` — виден Член+выше: 💬┃общий-чат, 🎮┃игровые-сессии, 🖼┃скрины (forum), 🔊┃голос-1, 🔊┃голос-2, 🔊┃голос-3 (voice), 🎧┃афк
   - `🌍 ОБЩЕЕ` — @everyone может читать и писать: 💬┃общий, 🛠┃оффтоп, 🔊┃лобби (voice)
   - `🎫 ЗАЯВКИ` — 🎫┃заявки-в-клан с setup_ticket_panel (support = Шеф+Зам+Офицер, welcome_message = шаблон заявки)
   - `🎂 ДНИ РОЖДЕНИЯ` — 🎂┃даты-дней-рождений (кнопка регистрации ДР, список именинников)
   - `🛡 РОЛИ И ДОСТУП` — 🎭┃выбор-ролей (self-role panel: подгруппы), ✅┃верификация (send_verification_panel → роль «Новичок», фактически Guest+Verify)
   - `🔒 ГРУППА <N>` × N подгрупп — видна только роли подгруппы: 💬┃чат, 🔊┃голос
5. Права: @everyone закрыт на КОМАНДОВАНИЕ, ЗАЯВКИ, ГРУППА*, ДНИ РОЖДЕНИЯ (view_channel=False), на ветках КОМАНДОВАНИЕ/ГРУППА* роли-членам view_channel=False, только нужной роли view_channel=True. send_messages на #объявления только высшие ранги.
6. **Отправка панелей**: rules embed → #правила; welcome embed → #инфо; тикет-панель → #заявки-в-клан; self-role (подгруппы) → #выбор-ролей; верификация → #верификация.
7. **Сохранение шаблона** в БД: `clan_<clan_name>` + настройки темы «clan».

Возвращает сводку операций и дальнейшие подсказки (как настроить внешних ботов).

### 2. Подсистема «Дни рождения»

- Таблица `birthdays (id, guild_id, member_id, name, month, day, year, created_at, UNIQUE(guild_id, member_id))`.
- AI-инструменты:
  - `register_birthday(member_name_or_id, date)` — регистрация/обновление даты («ДД.ММ[.ГГГГ]»).
  - `list_birthdays` — список именинников канала/сервера.
  - `set_birthday_channel(channel_name)` — канал для списка и поздравлений.
- Компонент `setup_birthday_panel(guild, channel_name)` — embed + кнопка «🎂 Отметить мой ДР» → модальное окно с вводом даты (формат ДД.ММ[.ГГГГ]), сохранение в БД, визатное сообщение. Кнопка работает для любых участников (не требует прав владельца).
- Фоновая задача `birthday_check_loop` (в on_ready, цикл с sleep 6ч): находит именинников сегодня (по UTC) и шлёт поздравление-пинг в настроенный канал ДР; обновляет список.
- Если канал ДР не настроен — fallback: канал по имени «даты-дней-рождений», затем `guild.system_channel`, затем первый доступный текстовый канал.

### 3. Подсистема «Приветствие»

- Таблица `welcome_config (guild_id PRIMARY KEY, channel_id, rules_text, guest_role_id, enabled)`.
- Инструменты:
  - `setup_welcome(channel_name, rules_text, guest_role_name, enabled)` — сохраняет конфиг, постит embed с правилами в канале (может вызываться из setup_clan_server и для обновления).
- Событие `on_member_join`: если включено — отправляет в канал приветствия embed «Добро пожаловать, @mention!» + правила, и выдаёт роль «Новичок» (если guest_role указана и позиция роли ниже позиции бота).

### 4. Бонус: внешние боты (Juniper и т.п.)

- `generate_bot_invite(application_id, permissions=0)` → возвращает готовую ссылку
  `https://discord.com/api/oauth2/authorize?client_id=<id>&permissions=<sum>&scope=bot%20applications.commands`
  и пошаговое объяснение (вставить ссылку браузеру → нажать Авторизовать → сообщить Луми имя).
- `configure_external_bot(bot_name, role_name, channel_name, view=True, send=True)` — создаёт роль для бота, выдаёт права на каналы, по возможности позиционирует роль выше нужных. (Применяется после того как владелец добавил бота.)
- Регистрация в `tools_map` + `TOOLS_DECLARATION`.

### 5. Изменения в существующем коде

- `tools_map` и `TOOLS_DECLARATION` в bot.py — новые/обновлённые описания.
- `SYSTEM_INSTRUCTION` — дополнение: ключевые сценарии «клановый сервер», «дни рождения», «приветствие», «добавь бота», «заявка в клан».
- `on_ready` — запуск фоновой задачи дней рождения.
- `on_member_join` — новое событие приветствия.

## Потоки данных

1. Пользователь пишет «Луми, сделай клан-сервер RUST».
2. run_agent вызывает setup_clan_server (без confirmed) → инструмент возвращает сводку-подтверждение → Луми отвечает вопросом в чат.
3. Пользователь подтверждает → Луми вызывает setup_clan_server(confirmed=True) → строится структура, сохраняется шаблон, в конце — поздравления/сводка.
4. ДР: участник жмёт кнопку → модалка → запись в БД → фоновая задача поздравляет в назначенный канал.
5. Приход участника: on_member_join → embed + правила + роль.
6. Внешний бот: generate_bot_invite → ссылка; после добавления владельцем — configure_external_bot.

## Обработка ошибок

- Каждый инструмент оборачивается в try/except, возвращает строку с ❌ (паттерн существующих инструментов), ошибки логируются в action_log через execute_tool.
- setup_clan_server: каждая операция отдельно в массиве результатов; итог — сводка успех/ошибка; шаблон сохраняется даже частично построенной структуры.
- Библиотека дат: парс дат в try/except, невалидный ввод → понятная ошибка.
- on_member_join устойчив к отсутствию конфига (no-op) и к отсутствию прав (catch discord.Forbidden).
- Фоновая задача с try/except на проход, при ошибке — continue, без падения бота.

## Тестирование

- `python -m py_compile` всех модулей (синтаксис).
- Импорт-смоук: краткий скрипт создаёт БД с новыми таблицами (init_db) без сети.
- Юнит-проверки парсера дат (валидные/невалидные форматы) — мини-скрипт.
- Ручная проверка в Discord владельцем: «настрой клан сервер», добавить ДР, дождаться приветствия. (Живые проверки требуют токена и одного из OWNER_IDS — из репозитория недоступны.)

## Дополнение (утв. 2026-08-19): «Луми всё умеет» + бесплатный fallback

### AI-цепочка устойчивости
1. Платная модель через релей (`BASE_URL`/`CLAUDE_API_KEY` из .env, сейчас neutralbeats + claude-sonnet-5).
2. При любой ошибке (402/таймаут/4xx/5xx, пустой ответ) — бесплатный анонимный Pollinations `https://text.pollinations.ai/openai` (UA-заголовок браузера, model=openai, без ключа; HTTP-клиент aiohttp, поддержка tool_calls).
3. Если и он упал — вежливый ответ-заглушка «AI временно недоступен», бот не падает.
Тикеты, эмбеды и панели обрабатываются независимо от AI.

### Системы
- **Уровни**: +10–25 XP за сообщение (кулдаун 60с), уровень = sqrt(xp/50), уведомление о левел-апе, тop-ы.
- **Экономика**: +5 кредитов за выдачу XP, покупка ролей из магазина, переводы, выдача владельцем.
- **Напоминания**: парсинг русского времени («через 2 часа», «завтра в 20:00», «20.02 15:00»), фоновая задача каждые 30с.
- **Авто-мод**: фильтр мата (редактируемый список), анти-спам (6+ сообщений за 5с), 3 варна → таймаут 30 мин; команды warn/учёт.
- **Голосования**: кнопки-варианты, итоги по кнопке. **Анонимка**: кнопка → модалка → анонимный пост. **Викторины**: opentdb.
- **Утилиты**: wttr.in (погода), open.er-api.com (курсы), MyMemory (перевод).

member_stats, economy, shop_items, warns, reminders, events, polls, automod_settings + birthdays, welcome_config.
